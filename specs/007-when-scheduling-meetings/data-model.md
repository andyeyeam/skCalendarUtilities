# Data Model: Optimized Meeting Slot Distribution

**Feature**: 007-when-scheduling-meetings
**Date**: 2025-01-30
**Phase**: 1 (Design & Contracts)

## Overview

This feature does **NOT introduce new data models** or modify existing Google Sheets schema. It operates entirely within the existing data structures defined in feature 006.

The optimization affects only the **algorithmic assignment** of people to meeting slots, not the data storage layer.

## Existing Data Models (Read-Only)

### Person (from src/models/Person.gs)

Represents an individual scheduled for one-to-one meetings.

**Fields**:
- `personId` (string): Unique identifier (ULID format)
- `name` (string): Full name of the person
- `calendarEventId` (string): Google Calendar event series ID (empty if no meeting scheduled)

**Storage**: Google Sheets tab `OneToOnePeople`
**Columns**: [personId, name, calendarEventId]

**Usage in Feature 007**:
- Read to get list of people for scheduling
- `calendarEventId` updated after event creation (existing behavior)
- No schema changes

---

### MeetingSlot (from src/models/MeetingSlot.gs)

Represents a weekly time slot available for one-to-one meetings.

**Fields**:
- `slotId` (string): Unique identifier (ULID format)
- `weekday` (string): Day of week (Monday, Tuesday, ..., Sunday)
- `startTime` (string): Start time in HH:MM format (e.g., "10:00")
- `endTime` (string): End time in HH:MM format (e.g., "11:00")

**Storage**: Google Sheets tab `OneToOneSlots`
**Columns**: [slotId, weekday, startTime, endTime]

**Usage in Feature 007**:
- Read by `expandSlotsIntoPeriods()` to generate available periods
- No schema changes
- No modifications to slot records

---

### OneToOneConfig (from src/services/OneToOneConfigService.gs)

Configuration settings for the one-to-one meeting scheduler.

**Fields**:
- `meetingDurationMinutes` (number): Duration of each meeting in minutes
- `minRecurrenceIntervalWeeks` (number): Minimum weeks between recurring meetings

**Storage**: Google Sheets tab `OneToOneConfig`
**Columns**: [settingName, settingValue]

**Usage in Feature 007**:
- Read `minRecurrenceIntervalWeeks` for recurrence calculation
- Read `meetingDurationMinutes` for period expansion
- No schema changes
- No new configuration fields

---

## Computed/Transient Data Structures

These are in-memory data structures used during algorithm execution (not persisted).

### Period (computed from MeetingSlot)

Represents a specific meeting time period within a slot.

**Structure**:
```javascript
{
  weekday: string,      // e.g., "Monday"
  startTime: string,    // e.g., "10:00"
  endTime: string       // e.g., "10:30"
}
```

**Source**: Generated by `expandSlotsIntoPeriods()`
**Lifecycle**: Created during scheduling, discarded after calendar events created
**Example**: A 2-hour slot with 30-min meetings produces 4 periods

---

### Assignment (computed during scheduling)

Represents the assignment of a person to a specific meeting period and week offset.

**Structure** (MODIFIED in Feature 007):
```javascript
{
  person: Person,         // Person object
  weekday: string,        // e.g., "Wednesday"
  startTime: string,      // e.g., "14:00"
  endTime: string,        // e.g., "14:30"
  weekOffset: number,     // ⚠️ NEW: Week offset within recurrence cycle (0-indexed)
  recurrenceWeeks: number // Recurrence interval in weeks
}
```

**Changes from Feature 006**:
- **Added**: `weekOffset` field to support interval stride distribution
- **Purpose**: Determines which week within the recurrence cycle the meeting starts

**Source**: Generated by `assignPeopleToPeriods()` (modified in Feature 007)
**Lifecycle**: Created during scheduling, used by `executeScheduling()`, then discarded

**Example Assignment**:
```javascript
{
  person: {personId: "01HMXYZ...", name: "Alice Smith", calendarEventId: ""},
  weekday: "Monday",
  startTime: "10:00",
  endTime: "10:30",
  weekOffset: 2,          // Start in week 2 of the cycle
  recurrenceWeeks: 4       // Repeat every 4 weeks
}
```

## State Transitions

### Meeting Lifecycle (unchanged from Feature 006)

```
┌─────────────────┐
│  No Meeting     │ person.calendarEventId = ""
└────────┬────────┘
         │
         │ createAllMeetings() or regenerateAllMeetings()
         ▼
┌─────────────────┐
│  Meeting        │ person.calendarEventId = "event_abc123"
│  Scheduled      │
└────────┬────────┘
         │
         │ deleteMeeting(personId) or regenerateAllMeetings()
         ▼
┌─────────────────┐
│  No Meeting     │ person.calendarEventId = ""
└─────────────────┘
```

**Feature 007 Impact**: None - state transitions remain identical

## Validation Rules (unchanged from Feature 006)

### Person Validation
- `personId`: Must be non-empty string
- `name`: Must be non-empty string (1-100 characters)
- `calendarEventId`: May be empty string (no meeting) or valid event ID

### MeetingSlot Validation
- `slotId`: Must be non-empty string
- `weekday`: Must be one of [Sunday, Monday, Tuesday, Wednesday, Thursday, Friday, Saturday]
- `startTime`: Must be valid HH:MM format (00:00 to 23:59)
- `endTime`: Must be valid HH:MM format, must be after startTime

### OneToOneConfig Validation
- `meetingDurationMinutes`: Must be positive integer (e.g., 30, 60)
- `minRecurrenceIntervalWeeks`: Must be positive integer (≥ 1)

---

## Data Volume Assumptions

- **People**: 1-100 individuals
- **Meeting Slots**: 1-10 weekly time slots
- **Periods**: 1-50 individual meeting periods (after slot expansion)
- **Assignments**: Equal to number of people (1-100)
- **Recurrence Interval**: 1-100 weeks (formula ensures capacity)
